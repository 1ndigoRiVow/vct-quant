# 提示词集：虎扑电竞评论情感分类（本地 BERT 微调）

> 配套《需求文档 v1.0》使用。
> 本文件包含 4 类提示词：
> 1. 数据标注提示词（人工 / LLM 辅助标注规范 + few-shot）
> 2. 微调管线代码生成提示词（驱动 AI Agent 写训练代码）
> 3. 推理服务代码生成提示词
> 4. 数据清洗提示词

> 可直接复制使用；占位符用 `{{...}}` 标注。

## 1. 数据标注提示词

### 1.1 标注系统提示词（System Prompt）

```
你是一名电竞社区（虎扑 JRs）评论情感标注员。你的任务是判断一条评论对
“所指选手/战队”的情感倾向，只输出以下三类的其中一种：

- positive：赞赏、支持、夸赞、期待、正向情绪
- neutral ：客观陈述、提问、科普、无情绪闲聊
- negative：批评、嘲讽、贬低、愤怒、负面情绪

标注规则：
1. 以“评论所指的选手/战队”为情感对象，不是评价比赛本身或解说。
2. 虎扑常见“阴阳怪气 / 反讽 / 黑话”要谨慎：表面夸实则嘲讽 → negative；
   表面骂实则玩梗夸 → positive。拿不准时按字面+语境综合判断。
3. 只含事实陈述、比分、时间、阵容等无情绪内容 → neutral。
4. 单纯提问、打卡、催更 → neutral。
5. 一条评论只能有一个标签。

只输出标签词（positive / neutral / negative），不要解释。
```

### 1.2 Few-shot 示例（放入 user 消息）

```
示例1
评论：ZmjjKK这把残局1v3太离谱了，未来可期
标签：positive

示例2
评论：这操作看得我血压飙升，赶紧下场别坑了
标签：negative

示例3
评论：今天比赛几点开始？想看EDG
标签：neutral

示例4
评论：不愧是“鼠鼠”，这波送得真有节目效果（嘲讽）
标签：negative

示例5
评论：虽然输了但XX今天打得还行，下把调整下就行
标签：neutral

待标注：
评论：{{comment_text}}
标签：
```

### 1.3 批量标注（LLM 辅助）Prompt 模板

```
请对下面 {{N}} 条虎扑电竞评论逐条打情感标签（positive/neutral/negative）。
严格按“1.1 标注规则”执行。输出 JSON 数组，每条含原文本与标签：

[
  {"text": "...", "label": "positive"},
  {"text": "...", "label": "neutral"}
]

评论列表：
{{jsonl_or_bullet_list}}

注意：
- 不要编造评论，只标注给出的内容。
- 反讽/黑话按 1.1 第2条判断。
- 输出必须是合法 JSON，不要额外说明。
```

## 2. 微调管线代码生成提示词（给 AI Agent）

> 用途：让 Codex / 编程 Agent 生成本地微调训练脚本。复制时替换 `{{...}}`。

```
任务：为「虎扑电竞评论 3 分类情感」任务，基于 hfl/chinese-roberta-wwm-ext
在本地（可能无外网）微调一个分类模型。请产出完整、可运行的 Python 代码与说明。

环境与约束：
- Python 3.13，依赖仅：torch、transformers、datasets、scikit-learn、numpy
- 必须支持 OFFLINE_MODE：若环境变量 OFFLINE_MODE=1，则从本地缓存
  （{{LOCAL_MODEL_DIR}}）加载模型与 tokenizer，不从 HuggingFace 下载
- 所有随机性用 seed=42 固定

数据：
- 训练/验证 JSONL，路径 {{TRAIN_JSONL}} / {{DEV_JSONL}}
- 字段：{"text": str, "label": "positive"|"neutral"|"negative"}
- label2id: positive=0, neutral=1, negative=2

要求产出：
1. train.py：
   - 加载 tokenizer 与模型（AutoModelForSequenceClassification, num_labels=3）
   - max_seq_length=128，batch_size=16，lr=2e-5，epochs=4，warmup_ratio=0.1，
     weight_decay=0.01，optimizer=AdamW
   - 按验证集 macro-F1 早停并保存最优 checkpoint 到 {{OUTPUT_DIR}}
   - 打印每轮 train loss、dev accuracy、macro-F1、每类 P/R、混淆矩阵
2. evaluate.py：在 dev 上输出上述指标并保存为 JSON 报告
3. requirements.txt：锁定版本，附离线安装说明
4. README 片段：训练命令、离线权重准备步骤

代码风格：函数化、有类型注解、关键步骤写中文注释、可重跑（幂等）。
不要使用未声明路径；不要假设有 GPU，CPU 也要能跑通基线（减小 batch 即可）。
```

## 3. 推理服务代码生成提示词（给 AI Agent）

```
任务：基于已训练好的本地模型 {{OUTPUT_DIR}}（chinese-roberta-wwm-ext 微调版，
3 分类情感），用 FastAPI 写一个本地推理服务。

接口：
- POST /predict   单条：body {"text": "..."}
  返回 {"label": "positive|neutral|negative",
        "probs": {"positive": 0.x, "neutral": 0.x, "negative": 0.x}}
- POST /predict_batch  批量：body {"texts": ["...", "..."]}
  返回列表，每项同 /predict

要求：
- 模型与 tokenizer 从 {{OUTPUT_DIR}} 本地加载，支持 OFFLINE_MODE（不联网）
- 单条推理延迟尽量低（可开启 torch 推理模式 / 可选 fp16）
- 提供 batch 打分函数，便于把 hupu_comments 未打分记录批量打标后写回字段
  sentiment（标签）、sentiment_pos/neu/neg（概率）、sentiment_updated_at
- 输出 requirements.txt 与启动命令（uvicorn）
- 代码含类型注解与中文注释，fail-fast（模型加载失败直接报错退出）
```

## 4. 数据清洗提示词

```
请清洗 {{RAW_COMMENTS_FILE}} 中的虎扑评论原始文本，为情感标注/训练做准备。
逐条处理并输出清洗后的 JSONL（{"text": ..., "match_id": ..., "player": ...}）。

清洗规则：
1. 去除首尾空白、不可见控制字符、零宽空格。
2. 去除 @昵称、#话题#、URL、表情包描述符（[图片] [doge] 等）但保留文字梗。
3. 合并多余空白与换行；单条文本截断到 200 字以内（超长大概率非单条评论）。
4. 过滤纯表情/纯符号/空文本（标注无意义）。
5. 保留虎扑黑话、谐音、反讽原文，不要“纠错”或改写语义。
6. 去重（同 match_id + 同 text 只留一条）。

输出：合法 JSONL，不要额外说明文字。不要编造 match_id / player，缺失则留空字符串。
```
